# LessonLens — демонстрация (демо-сценарий)

Этот документ описывает, как за 10–15 минут показать весь продукт на готовых демо-данных: от загруженной записи
урока до отчётов для преподавателя, методиста и родителя, включая родительский кабинет в браузере и Telegram.

**Два урока** (10 и 3 дня назад, 16:00 по Алматы) с одной и той же записью `demo/lesson_01/lesson.mp4`.
Второй урок нужен, чтобы в прогрессе ученика была история (`times_seen = 2`, динамика по урокам).

**Демо-урок** (`demo/lesson_01/script.md` — полный сценарий с таймкодами, ≈34 минуты):

* тема — падежные окончания существительных: дательный и предложный падеж; второй сюжет — правописание -тся/-ться;
* ученик свободно переключается на казахский, преподаватель опирается на казахские падежи (мектепке / мектепте);
* наблюдаемые сигналы, которые должен «поймать» анализ:
  * **13:50** ученик говорит «понял», **14:20** — ошибка «я иду **в школе**» (нужно «в школу»);
  * **19:05** — та же ошибка повторяется после переобъяснения («ходили **в библиотеке**») → переобъяснение на доске;
  * упражнение из 6 заданий — **4 решены самостоятельно**, 2 с подсказкой;
  * на экране напечатано «хочет **учится**» (нужно «учиться»), позже — исправленный вариант;
  * итоговая проверка пройдена: ученик сам формулирует правило.

**Кадры экрана** (`demo/lesson_01/frames/0000.jpg … 0011.jpg`, 1280×720, без лиц): раскладка Zoom с аватарами, титульный
слайд, таблица окончаний, слайд «Куда? или Где?», упражнения, доска с разбором ошибки, документ с ответами ученика
(с ошибкой и после исправления), итоги, домашнее задание.

### Важно: mock-провайдеры

Демо не требует ключей STT/LLM. При сидировании принудительно включаются `STT_PROVIDER=mock`, `LLM_PROVIDER=mock`,
`MESSAGING_PROVIDER=mock`:

* mock-STT возвращает `demo/lesson_01/transcript.json` (307 реплик, таймкоды до 34:06) **независимо от аудио**;
* mock-LLM возвращает `demo/lesson_01/analysis.json` (валидный `LessonAnalysis`) **независимо от транскрипта и кадров**;
* `lesson.mp4` — техническая заглушка: 12 демо-кадров, сжатые до ~90 секунд, с тихим синтетическим звуком вместо речи.
  Она нужна только для того, чтобы пайплайн честно прошёл `ffprobe` → извлечение аудио → ключевые кадры. Сцены подобраны так,
  что детектор смены сцены извлекает ровно 12 кадров в том же порядке, что и `frames.json`, поэтому ссылки `frame_ids`
  в анализе указывают на правильные изображения.

Чтобы отчёт и кадры совпадали, сидирование после обработки выставляет кадрам таймкоды из `frames.json`
(02:40, 03:20, 11:16 …) и уроку длительность ≈ 34 минуты: клик по таймкоду отчёта подсвечивает нужный кадр, подписи
кадров совпадают с эпизодами. Единственное отличие от настоящей записи — сам плеер крутит 90-секундный ролик, поэтому
позиция видео не совпадает с таймкодом. Если нужна полная синхронизация (видео 35 минут, кадры извлекаются ровно на
таймкодах `frames.json`), запустите `python -m app.seed_demo --reset --realtime` — сборка занимает около минуты,
файл ≈ 10 МБ.

## 2. Запуск

```bash
# 1. Postgres 16 на 127.0.0.1:5432 (пользователь/пароль/БД lessonlens), ffmpeg/ffprobe в PATH
cd backend && source .venv/bin/activate
alembic upgrade head

# 2. Демо-данные: центр, персонал, ученик, родитель, два обработанных урока
python -m app.seed_demo            # идемпотентно: повторный запуск ничего не дублирует
python -m app.seed_demo --reset    # удалить демо-центр и его медиафайлы, создать заново
python -m app.seed_demo --reprocess   # заново прогнать пайплайн для уже обработанных уроков
python -m app.seed_demo --realtime    # собрать видео с реальными таймкодами (35 мин, ≈10 МБ)

# 3. API и фронтенд
uvicorn app.main:app --reload --port 8000
cd ../frontend && npm install && npm run dev     # http://localhost:5173
```

Seed-скрипт печатает в конце логины, **magic-ссылку** родителя (`http://localhost:5173/p/<token>`, действует 72 часа,
можно открывать повторно) и инструкции по Telegram. Ссылку можно пересоздать в любой момент: «Родители → Создать
magic-ссылку» или повторный запуск `python -m app.seed_demo`.

Пересборка фикстур (только если вы их меняли):

```bash
python demo/make_frames.py        # кадры + frames.json (Pillow, шрифт DejaVu Sans)
python demo/make_transcript.py    # transcript.json + script.md из одного сценария
python demo/build_demo_media.py   # lesson.mp4 (~90 с, ≈1.6 МБ); --realtime для реальных таймкодов
```

`analysis.json` редактируется вручную; проверить его можно так:

```bash
cd backend && python -c "import json; from app.schemas.analysis import LessonAnalysis; \
LessonAnalysis.model_validate(json.load(open('../demo/lesson_01/analysis.json'))); print('ok')"
```

## 3. Сценарий показа (персонал)

Войдите как `admin@demo.kz` (владелец видит всё).

1. **Дашборд (`/`)** — сводка центра: уроков всего / за неделю, доля уроков с проверкой целей, счётчик «требуется разбор»
   (в демо — 0), последние уроки. Покажите, что оба урока в статусе «Готово».
2. **Уроки (`/lessons`)** — список с фильтрами и статусами. Откройте последний урок (3 дня назад).
3. **Страница урока (`/lessons/:id`)** — вверху таймлайн обработки (uploaded → probing → … → done).
   * **Вкладка «Для учителя»** — главный экран продукта. Покажите:
     * эпизоды с таймкодами: ошибка 14:20 «иду в школе» → переобъяснение 14:22 → повторилась в 16:09; ошибки 16:09 и 19:05
       → переобъяснение 19:17 → повторилась в 21:51 (бейдж «после объяснения» — собственный флаг анализа); ранние
       оговорки 01:34 и 07:35 (падежные окончания) к переобъяснениям «куда/где» не привязаны;
     * «что ученик сделал сам» (самокоррекция «к бабушке», правило дательного падежа своими словами, 4 задания из 6);
     * замеченное на экране: кадр #8 — «хочет учится» с пометкой об ошибке, кадр #9 — исправленный вариант;
     * рекомендации с готовыми формулировками вопросов («Скажи два предложения — одно со словом «иду»…»);
     * таймкоды кликабельны — подсвечивается соответствующий кадр (в карточке и в ленте под видео); плеер при этом
       показывает 90-секундную заглушку, если демо собрано без `--realtime`.
   * **Вкладка «Для методиста»** — индикаторы качества без рейтинга учителя: цели проверены ✔, трудности выявлены (i —
     нейтральный факт об уроке),
     переобъяснение было ✔, разбор методиста не требуется; доли речи 68 % / 32 %; задач 6, самостоятельно 4;
     краткое резюме структуры урока.
   * **Вкладка «Для родителя»** — то, что получит мама: тема простыми словами, что получилось, где было трудно, что
     повторить дома, поддерживающая фраза; рядом — предпросмотр Telegram-сообщения (≤ 1500 символов) и кнопка
     повторной отправки.
   * **«Транскрипт»** — реплики учитель/ученик с таймкодами и казахскими вставками; **«Кадры»** — 12 кадров экрана.
4. **Ученики → Данияр Ахметов (`/students/:id`)** — прогресс по навыкам: «Выбор падежа: куда? / где?» — трудности,
   «-тся / -ться», «Падежные окончания» — в развитии; у каждого навыка история с таймкодами по двум урокам
   (`times_seen = 2`). Объясните принцип честности: «тему прошли» ≠ «тему усвоили» — статус «освоено» появляется только
   при самостоятельных правильных ответах на нескольких уроках.
5. **Загрузка (`/lessons/upload`)** — покажите форму: файл, ученик, преподаватель, дата, **обязательная галочка согласия**.
   Можно загрузить тот же `demo/lesson_01/lesson.mp4` — обработка займёт секунды (mock-провайдеры), статус обновляется
   на странице урока автоматически.
6. **Роли**: выйдите и войдите как `teacher@demo.kz` — преподаватель видит только свои уроки, вкладка «Для методиста»
   недоступна; как `methodist@demo.kz` — всё, кроме управления персоналом.

## 4. Родительский поток

### В браузере (всегда работает)

1. Скопируйте magic-ссылку из вывода seed-скрипта (или «Родители → Создать magic-ссылку»).
2. Откройте её в телефоне или в узком окне браузера (кабинет мобильный): `/p/<token>` обменивает токен на вход родителя
   и перенаправляет в `/parent`.
3. `/parent` — карточка ребёнка: последний урок, количество уроков, сводка навыков.
4. `/parent/students/:id` — список уроков с краткими карточками отчёта; переключатель «прогресс» — навыки и динамика.
5. `/parent/students/:id/lessons/:lessonId` — полный отчёт по уроку: тема, что получилось, что было трудно,
   что повторить дома (3 конкретных задания на 10–15 минут), поддерживающая фраза.
6. `/parent/settings` — канал уведомлений (Telegram / WhatsApp / не присылать) и язык.

Ссылка действует 72 часа и может открываться повторно (родитель возвращается из Telegram). После истечения — страница
`/parent/expired` и новая ссылка через `/progress` в боте или через персонал.

### В Telegram (нужен токен бота)

1. Создайте бота у @BotFather, положите токен в `.env`: `TELEGRAM_BOT_TOKEN=...`, `TELEGRAM_MODE=polling`
   (для webhook — `TELEGRAM_WEBHOOK_URL` и `TELEGRAM_WEBHOOK_SECRET`, см. `docs/MESSAGING.md`).
2. Уберите `MESSAGING_PROVIDER=mock` из окружения (seed ставит его только на время сидирования) и запустите API:
   `uvicorn app.main:app --port 8000` — polling стартует в lifespan.
3. На странице «Родители» нажмите **«Отправить приглашение»**: пока chat_id неизвестен, уведомление получит статус
   `skipped`, а в payload будет deep-link `https://t.me/<бот>?start=DEMO2026` и magic-ссылка — их можно переслать
   родителю вручную. Или просто откройте бота и отправьте `/start DEMO2026`.
4. Бот привяжет chat_id к Гульнаре Ахметовой и пришлёт приветствие с кнопкой в кабинет.
5. На странице урока → вкладка «Для родителя» → **«Отправить родителям»** (`POST /api/lessons/{id}/reports/parent/send`):
   родитель получает отчёт в HTML-разметке Telegram и свежую magic-ссылку. Команда `/progress` в боте присылает
   сводку по навыкам и новую ссылку в кабинет.

Все отправки пишутся в таблицу `notifications` (статусы `sent / failed / skipped`) — покажите их в карточке родителя.

## 5. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| `Ошибка: таблицы не найдены` | `cd backend && alembic upgrade head` |
| `ffmpeg не найден` | установите ffmpeg/ffprobe (`apt install ffmpeg`) или задайте `FFMPEG_BIN` / `FFPROBE_BIN` |
| Урок в статусе `failed` | поле `status_message` на странице урока / `lessons.error` в БД; `python -m app.seed_demo --reprocess` |
| Кадры в отчёте не совпадают с описанием | пересоберите видео: `python demo/build_demo_media.py` и `--reprocess` (кадры извлекаются из mp4) |
| Нет кириллицы на кадрах | нужен шрифт DejaVu (`fonts-dejavu`) либо `pip install matplotlib` (встроенный DejaVuSans.ttf) |
| Magic-ссылка истекла | «Родители → Создать magic-ссылку» или повторный `python -m app.seed_demo` |
| Хочется «честные» таймкоды кадров | `python -m app.seed_demo --reset --realtime` (видео 35 мин, ≈10 МБ, сборка ~1 мин) |

## 7. Автопроверка демо (browser smoke)

Весь путь из разделов 3–4 проходит автоматический Playwright-тест `backend/tests/e2e/test_smoke.py`: вход
`admin@demo.kz` → дашборд с числами → два урока в статусе «Готово» → вкладки «Для учителя» / «Для методиста» /
«Для родителя», загрузка миниатюр кадров (`/api/media/frames/…` → 200) → прогресс ученика → «Создать magic-ссылку»
→ кабинет родителя на viewport 390×844 (ребёнок, уроки, отчёт, прогресс). Любой ответ API 5xx во время прогона
валит тест. Скриншоты обновляются в `docs/screenshots/`.

```bash
cd backend && python -m app.seed_demo --reset          # демо-данные
uvicorn app.main:app --port 8000 &                     # API
(cd ../frontend && npm run dev -- --port 5173) &       # фронтенд
E2E=1 PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers .venv/bin/python -m pytest tests/e2e -q   # или: make e2e
```

Без `E2E=1` тест пропускается (так он не мешает обычному `pytest`). Если браузеры Playwright не предустановлены —
`.venv/bin/playwright install chromium`. Переменные: `E2E_BASE_URL` (по умолчанию `http://127.0.0.1:5173`),
`E2E_EMAIL`/`E2E_PASSWORD`, `E2E_SCREENSHOT_DIR`, `E2E_TIMEZONE` (по умолчанию `Asia/Almaty`), `E2E_HEADED=1`.
