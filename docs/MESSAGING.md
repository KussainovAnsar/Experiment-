# Уведомления родителям: Telegram-бот и WhatsApp

Модуль C LessonLens: как создать и подключить Telegram-бот, чем отличаются режимы polling и webhook, как
работает пригласительная ссылка (deep link), что нужно для WhatsApp Cloud API и какие данные покидают систему.

Код: `backend/app/bot/telegram.py` (aiogram 3), `backend/app/api/telegram.py` (webhook),
`backend/app/services/notifications.py` (что/кому/когда), `backend/app/providers/messaging/*` (адаптеры каналов).

---

## 1. Что получает родитель

1. **Приглашение** (`POST /api/parents/{id}/send-invite` или кнопка «Отправить приглашение»): приветствие,
   объяснение, какие отчёты будут приходить, имена детей, ссылка в кабинет родителя (magic-ссылка) и ссылка на
   Telegram-бот (deep link), если Telegram ещё не привязан.
2. **Отчёт после каждого урока** (стадия `notifying` пайплайна или `POST /api/lessons/{id}/reports/parent/send`):
   HTML-сообщение ≤ 1500 символов — тема простыми словами, что получилось самостоятельно, где были ошибки, что
   повторить дома, поддерживающая фраза, и кнопка **«Открыть кабинет»** со свежей magic-ссылкой.
3. **По запросу** — команда `/progress` в боте: последний отчёт по каждому ребёнку и новая ссылка в кабинет.

Канал выбирается полем `parents.preferred_channel`: `telegram` | `whatsapp` | `none`. Каждая попытка отправки
записывается в таблицу `notifications` со статусом `sent` / `failed` / `skipped`, текстом ошибки и `payload`
(`channel`, `has_portal_link`, `deep_link`, `reason`). Сама magic-ссылка в `payload` отчёта **не сохраняется**;
исключение — недоставленное приглашение (`skipped`): там `magic_url` оставлен намеренно, чтобы администратор мог
переслать ссылку вручную.

| Ситуация | Статус | Что в `error` / `payload.reason` |
|---|---|---|
| Telegram, чат привязан, API ответил ok | `sent` | `provider_message_id` = id сообщения |
| Telegram, родитель ещё не открыл бот | `skipped` | `telegram_not_linked`, в `payload.deep_link` — ссылка на бот |
| `preferred_channel = none` | `skipped` | `channel_none` |
| WhatsApp выключен / нет токена, Telegram без токена | `failed` | `provider_not_configured`, текст подсказывает переменную окружения |
| Ошибка API / сети | `failed` | текст ответа провайдера (например, `Telegram API 403: Forbidden: bot was blocked by the user`) |

Сервис уведомлений **никогда не бросает исключение** из-за провайдера — пайплайн урока не падает, если
мессенджер недоступен.

## 2. Telegram-бот: создание и настройка

### 2.1 Создать бота в @BotFather

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Укажите отображаемое имя (например, «LessonLens — отчёты для родителей») и **username** (должен
   заканчиваться на `bot`, например `lessonlens_center_bot`). Username нужен для deep-link.
3. BotFather выдаст токен вида `123456789:AAE...`. Положите его в `.env`:

```env
TELEGRAM_BOT_TOKEN=123456789:AAE...
TELEGRAM_MODE=polling            # или webhook, см. §2.3
```

4. Рекомендуется: `/setdescription` — коротко о боте, `/setcommands`:

```
start - Подключиться по пригласительному коду
progress - Последние отчёты по занятиям
stop - Отключить уведомления
help - Справка
```

Пустой `TELEGRAM_BOT_TOKEN` = бот выключен: уведомления в Telegram записываются как `failed`
(«TELEGRAM_BOT_TOKEN не задан»), deep-link не формируется, polling не запускается.

### 2.2 Команды бота

| Команда | Поведение |
|---|---|
| `/start КОД` | Ищет родителя по `invite_code` (регистр не важен), привязывает `telegram_chat_id`, отвечает приветствием с именами детей и кнопкой «Открыть кабинет» (свежая magic-ссылка). Код **одноразовый**: после привязки он заменяется новым; родитель, уже привязанный к другому чату, никогда не перепривязывается (ответ «код уже использован, обратитесь в центр» — администратор снимает привязку кнопкой «Отозвать доступ»); если этот Telegram уже привязан к другому родителю — объясняет, что нужно обратиться в центр. После 5 неверных кодов за час чат игнорируется. Повторный `/start` из привязанного чата безопасен (в том числе со старым кодом из пересланной ссылки); после `/stop` снова включает канал `telegram`. |
| `/start` без кода | Объясняет, где взять код у центра. |
| `/progress` | Для каждого ребёнка — последний родительский отчёт (HTML, с новой magic-ссылкой) или «Отчётов пока нет». |
| `/stop` | `preferred_channel = none`, «Вы отключили уведомления». Отчёты остаются доступны в кабинете. |
| `/help` | Список команд и примечание о приватности. |

Все ответы — на русском, уважительным тоном, без оценок преподавателя. В логи пишутся только id.

### 2.3 Polling или webhook

| | `TELEGRAM_MODE=polling` (по умолчанию) | `TELEGRAM_MODE=webhook` |
|---|---|---|
| Как получаем обновления | Приложение само опрашивает `getUpdates` в фоновой asyncio-задаче (запускается в lifespan FastAPI) | Telegram сам присылает POST на наш HTTPS-адрес |
| Требования | Исходящий интернет; публичный адрес не нужен — подходит для пилота и локальной разработки | Публичный HTTPS с валидным сертификатом (порты 443/80/88/8443), доступный из интернета |
| Несколько экземпляров API | Только **один** процесс должен делать polling (иначе Telegram вернёт 409 Conflict) | Любое число экземпляров за балансировщиком |
| Настройка | ничего, кроме токена | `TELEGRAM_WEBHOOK_URL`, `TELEGRAM_WEBHOOK_SECRET` (случайная строка ≥ 32 символов) |

Webhook-эндпоинт: `POST /api/telegram/webhook/{secret}`. Секрет в пути сравнивается с
`TELEGRAM_WEBHOOK_SECRET` константным временем; при несовпадении **или пустой настройке** — `403`. Если Telegram
передаёт заголовок `X-Telegram-Bot-Api-Secret-Token` (мы указываем `secret_token` при `setWebhook`), он тоже
должен совпасть. При старте в режиме webhook приложение само вызывает `setWebhook`:
`TELEGRAM_WEBHOOK_URL` может быть базовым адресом API (`https://api.center.kz` → к нему добавится
`/api/telegram/webhook/<secret>`) или уже полным URL. Ошибки обработчика логируются и отвечают `200`, иначе
Telegram будет бесконечно повторять то же обновление.

Переключение webhook → polling: приложение при старте polling вызывает `deleteWebhook`. Обратно — просто
смените `TELEGRAM_MODE` и перезапустите.

### 2.4 Deep link и username бота

Пригласительная ссылка: `https://t.me/<bot_username>?start=<invite_code>`. Родитель нажимает на неё, Telegram
открывает бот и подставляет `/start <invite_code>` — код вводить не нужно. Username получается один раз при
старте через `getMe` и кэшируется; переменная `TELEGRAM_BOT_USERNAME` переопределяет его (полезно в режиме
webhook, когда до первого обновления `getMe` не вызывался, и в тестах). Пока username неизвестен или бот
выключен, `deep_link_for(parent)` возвращает `None`, и в приглашении остаётся только magic-ссылка.

`invite_code` — 8 символов из однозначного алфавита (без 0/O, 1/I/L), чтобы его можно было продиктовать по
телефону. Он виден владельцу/методисту на карточке родителя (преподаватель его не получает, в том числе в
ответах `POST /api/lessons/{id}/reports/parent/send`), действует до первой успешной привязки и заменяется новым
при привязке и при «Отозвать доступ» (`POST /api/parents/{id}/revoke-access`).

## 3. WhatsApp (Meta Cloud API) — заготовка

Адаптер `providers/messaging/whatsapp.py` отправляет текстовые сообщения через
`POST https://graph.facebook.com/v21.0/{WHATSAPP_PHONE_NUMBER_ID}/messages`, преобразуя HTML отчёта в
форматирование WhatsApp (`*жирный*`, `_курсив_`, ссылки текстом). По умолчанию выключен:

```env
WHATSAPP_ENABLED=false
WHATSAPP_PHONE_NUMBER_ID=
WHATSAPP_ACCESS_TOKEN=
```

При `WHATSAPP_ENABLED=false` отправка завершается статусом `failed` с понятной ошибкой — ни одна сторонняя
система не вызывается. Номер берётся из `parents.whatsapp_phone`, иначе из `parents.phone`, нормализуется в
E.164 без «+» (`8 701 …` → `7701…`).

### 3.1 Что нужно сделать центру до включения

1. **Meta Business Account и верификация бизнеса.** Без верификации доступен только тестовый номер и до
   5 получателей из списка; для реальных родителей нужна верификация (учредительные документы, сайт/соцсети,
   обычно 2–10 рабочих дней). Для казахстанского ТОО/ИП — документы о регистрации и подтверждение адреса.
2. **WhatsApp Business Platform → номер телефона.** Нужен номер, не привязанный к обычному приложению WhatsApp
   (его можно перенести). Отображаемое имя проходит проверку Meta.
3. **Системный пользователь и постоянный токен** с правами `whatsapp_business_messaging` и
   `whatsapp_business_management` → `WHATSAPP_ACCESS_TOKEN`. Временные токены из панели живут 24 часа — не
   используйте их в продакшене.
4. **Шаблоны сообщений (message templates).** Произвольный текст можно отправить только в течение **24 часов**
   после последнего сообщения родителя боту («окно обслуживания»). Отчёт после урока почти всегда приходит вне
   этого окна, поэтому для продакшена нужен **одобренный шаблон категории Utility**, например:
   «Здравствуйте, {{1}}! Готов отчёт по занятию {{2}} ({{3}}). Открыть: {{4}}» с переменными имя родителя /
   предмет / дата / ссылка. Одобрение — обычно до 24 часов. Текущая реализация отправляет свободный текст; при
   ответе API с кодом 131047 («Re-engagement message») уведомление помечается `failed` с подсказкой про шаблон.
   Поддержка `type: template` — следующий шаг, интерфейс `Messenger` для этого менять не нужно.
5. **Согласие (opt-in).** Meta требует явного согласия получателя на сообщения в WhatsApp. Фиксируйте его в
   договоре с родителем и/или в форме центра; поле `preferred_channel=whatsapp` должно выставляться только после
   согласия.
6. **Стоимость.** С 1 июля 2025 Meta тарифицирует **каждое шаблонное сообщение** (ранее — «разговор» за
   24 часа) по категории: Utility дешевле Marketing; сообщения в открытом окне обслуживания и Utility-шаблоны
   внутри окна бесплатны. Ставка зависит от страны получателя; для Казахстана ориентируйтесь на несколько
   центов за Utility-сообщение, актуальные цены — в разделе Pricing документации WhatsApp Business Platform.
   Первые 1000 служебных разговоров в месяц бесплатны (условие периодически меняется — проверяйте).
7. **Webhook входящих** (ответы родителей, статусы доставки) — не реализован в MVP; бот WhatsApp не ведёт
   диалог, только отправляет.

Альтернатива для Казахстана: официальные BSP-партнёры Meta (например, Infobip, 360dialog) дают тот же Cloud
API через свой кабинет и помогают с верификацией; адаптер подключается к их URL сменой `api_base`.

## 4. Тестовый и mock-режим

* `MESSAGING_PROVIDER=mock` — переменная окружения (не входит в `Settings`): все каналы идут в
  `app.providers.messaging.mock`, сообщения накапливаются в списке `mock.sent`, ничего не отправляется. Так
  работают тесты и демо без токенов.
* Для ручной проверки Telegram без публичного адреса достаточно `TELEGRAM_MODE=polling` и реального токена.
* Тесты: `pytest tests/test_notifications_*.py tests/test_bot_*.py` (нужна БД `lessonlens_test`).

## 5. Приватность и безопасность

* **В сообщениях — только имя ребёнка** (первое слово ФИО) и учебные наблюдения: без фамилии, школы, класса,
  оценок преподавателя и «диагнозов». Полный отчёт — только в кабинете по ссылке.
* **Magic-ссылка** `PUBLIC_BASE_URL/p/<token>`: токен 32 байта, в БД хранится только SHA-256; срок действия
  `MAGIC_LINK_TTL_HOURS` (по умолчанию 72 ч), после чего ссылку нужно получить заново (`/progress`, кнопка в
  интерфейсе центра). Ссылку можно открывать повторно до истечения срока — родители часто возвращаются к
  сообщению в Telegram. При каждом уведомлении создаётся **новая** ссылка.
* **Не храним ссылку в `notifications.payload`** (кроме недоставленных приглашений) и не пишем её в логи.
  В логах — только id родителя/урока и коды ошибок провайдера.
* **Привязка чата** однозначна (`telegram_chat_id` уникален): один Telegram — один родитель. Конфликт
  разрешает администратор центра (очистить `telegram_chat_id` у старой записи).
* **Отзыв согласия** — `/stop` в боте или `PATCH /api/parent/me {preferred_channel: "none"}`; данные ребёнка
  при этом не удаляются (см. `docs/LEGAL_KZ.md` о сроках хранения).
* Токен бота и токен WhatsApp — только в `.env`/секретах окружения, никогда в репозитории. Webhook-секрет —
  случайная строка, сравнение константным временем.
