# Скорость обработки урока

Цель — чтобы центр получал отчёты через 1–3 минуты после загрузки записи, а не через полчаса.
Все цифры ниже получены на одной машине: 4 vCPU, 15 ГБ RAM, без GPU.

## Тестовая запись

`backend/benchmarks/make_lesson_video.py` собирает реалистичную запись урока:

- 45 минут, 1920×1080, 25 кадров/с, H.264;
- демонстрация экрана: слайды демо-урока меняются в реальные моменты урока;
- подвижное «окно камеры» в углу, чтобы декодер работал как на настоящем Zoom;
- речь на русском и казахском с паузами, AAC-дорожка;
- размер 93 МБ.

```bash
cd backend
python benchmarks/make_lesson_video.py --minutes 45 --height 1080
python benchmarks/media_bench.py benchmarks/data/lesson_45m_1080p.mp4 --label my-run
python benchmarks/pipeline_bench.py benchmarks/data/lesson_45m_1080p.mp4 --stt-delay 40 --llm-delay 75
```

## Результат

Собственная обработка: всё, кроме распознавания речи и ИИ-анализа.

| Этап | Было | Стало | Что изменилось |
|---|---|---|---|
| Ключевые кадры | 81 с | 3.2 с | сканируются только опорные кадры видео в 320×180, 4 процесса параллельно; полный кадр декодируется только для выбранных моментов |
| Аудио для облачного распознавания | 5.5 с (WAV 86 МБ) | 2.4 с (исходная AAC-дорожка, 16 МБ) | дорожка копируется без перекодирования; загрузка в облако в 5 раз меньше |
| Аудио для локального Whisper | 5.5 с | 5.5 с | без изменений, WAV нужен модели |
| Порядок этапов | последовательно | кадры параллельно с распознаванием речи | кадры готовы раньше текста и не добавляют времени |
| **Итого без провайдеров** | **76.6 с** | **3.4 с** | замер `pipeline_bench.py` на старом и новом коде |

Полный цикл с облачными провайдерами. Задержки провайдеров заданы как допущение: распознавание 40 с, анализ 75 с.

| | Было | Стало |
|---|---|---|
| Время от загрузки до отчётов | 196.5 с | 117.9 с |
| Доля наших этапов | 81 с из 196 | 3 с из 118 |

Теперь почти всё время уходит на внешние сервисы. Дальнейшее ускорение возможно только выбором провайдеров.

## Где теперь время и что с ним делать

| Этап | 45-минутный урок | Рычаг |
|---|---|---|
| Распознавание речи, облако (Deepgram, ElevenLabs, AssemblyAI) | обычно десятки секунд по данным провайдеров, здесь не измерялось | основной вариант для пилота |
| Распознавание речи, Whisper large-v3-turbo на CPU | ≈ 35 мин (RTF 0.78, бенчмарк в `benchmarks/`) | только для офлайн-режима; урок ждёт в очереди |
| Распознавание речи, Whisper на GPU | ≈ 1–2 мин, оценка по опубликованным замерам faster-whisper | `WHISPER_DEVICE=auto`, пакетный режим включается сам |
| ИИ-анализ, Claude Sonnet | ≈ 1–1.5 мин: ~5 тыс. токенов ответа | следующий шаг: разбор кадров отдельным запросом, пока идёт распознавание |
| Отчёты, прогресс, уведомления | < 0.2 с | — |

Локальный Whisper стал примерно в 2 раза быстрее, чем был в коде: декодирование теперь жадное (`WHISPER_BEAM_SIZE=1`), раньше стоял beam 5. Цифры бенчмарка получены именно в жадном режиме.

## Что сделано в коде

1. **Ключевые кадры** (`app/pipeline/media.py`, раздел keyframes).
   - Сканируются только опорные кадры видео (`-skip_frame nokey`) в сером 320×180.
   - Длинная запись делится на 4 куска, каждый сканирует свой процесс ffmpeg.
   - Если опорные кадры реже `KEYFRAME_SCAN_MAX_GAP_SEC`, включается выборка 1 кадр/с без B-кадров и деблокинга. Она тоже параллельная: 19 с на 45 минут.
   - Пиксели, которые постоянно меняются (окно камеры, видео в презентации), маскируются.
   - Большое изменение неподвижной части экрана считается новым слайдом. Маленькое, вроде напечатанного слова, считается правкой. Перед сменой слайда сохраняется его последнее состояние, поэтому ответы ученика с ошибками попадают в анализ.
   - Полноразмерные кадры извлекаются только для выбранных моментов, 4 процесса параллельно.
2. **Аудио.** Облачные провайдеры получают исходную дорожку без перекодирования. AAC копируется в `.m4a`, Opus и Vorbis в `.ogg`, MP3 как есть. Прочие форматы перекодируются в Opus в самом быстром режиме. Локальный Whisper получает WAV.
3. **Параллельные ветки** (`app/pipeline/runner.py`). Ветка «аудио → распознавание» и ветка «кадры» идут одновременно.
4. **Пульс долгих этапов.** Каждые `PIPELINE_HEARTBEAT_SEC` секунд статус урока обновляется: «Распознаём речь · 3 мин 20 с». Центр видит, что работа идёт. Долгое распознавание больше не принимается за зависший урок.
5. **Время обработки сохраняется** в `lessons.processing_stats`: всего и по этапам. На странице урока видно «Обработано за 1 мин 58 с».
6. **Воркер** обрабатывает `WORKER_CONCURRENCY` уроков одновременно, по умолчанию 2. Вечерняя пачка уроков больше не стоит в очереди друг за другом. Для локального Whisper на CPU ставьте 1.
7. **Исправлена ошибка** в адаптерах Deepgram и AssemblyAI. Файл передавался в асинхронный HTTP-клиент синхронным объектом, и httpx отказывался отправлять запрос. Теперь файл стримится.

## Что ещё можно ускорить

- **Загрузка записи.** 45 минут Zoom в 1080p весят 200–500 МБ. При исходящем канале 20 Мбит/с это 1.5–3.5 минуты ещё до начала обработки. Решение — интеграция с облачными записями Zoom: сервер сам скачивает запись после урока, пользователю ничего не нужно загружать.
- **Разбор кадров во время распознавания.** Отдельным запросом к модели описать кадры, пока распознаётся речь, и отдать основному анализу готовые описания. Это сократит ответ основного запроса на 1–1.5 тыс. токенов, примерно 15–20 с.
- **GPU для локального Whisper,** если записи нельзя отправлять в облако по юридическим причинам. Подробнее в `docs/LEGAL_KZ.md`.
