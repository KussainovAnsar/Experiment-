# Провайдеры STT и LLM для LessonLens: бенчмарк и исследование (октябрь 2026)

Документ отвечает на три вопроса для пилота «русский язык в казахской школе, один учитель — один ученик, запись Zoom/Meet»:

1. Насколько хорошо локальные открытые модели (семейство Whisper) распознают русскую, казахскую и смешанную классную речь — **измерено здесь** на синтетическом датасете (`backend/benchmarks/`).
2. Что умеют облачные STT-провайдеры по русскому и казахскому в 2026 году — **кабинетное исследование**, всё, что помечено «не измерялось здесь», взято из документации и публичных источников, а не из наших прогонов.
3. Какой провайдер взять в пилот по умолчанию, что проверять следующим на реальных записях, сколько это стоит за час урока и как решать задачу «кто говорит» (диаризацию). Плюс рекомендация по LLM-части.

> Главная оговорка. Ключей к облачным STT и LLM в среде разработки нет, Hugging Face заблокирован egress-политикой. Поэтому живое сравнение покрывает **только** открытые модели Whisper, запущенные локально, а аудио **синтезировано TTS (Piper)**. Синтетическая речь — чистая, ровная, без перебиваний, шума комнаты и детских голосов. Реальные записи Zoom дадут заметно худшие цифры; наши результаты — это **верхняя граница** качества и, главное, **относительное** сравнение моделей и режимов.

## 1. Методика локального бенчмарка

### 1.1 Датасет (`backend/benchmarks/make_dataset.py`)

| Подмножество | Говорящий | Содержание | Реплик | Аудио |
|---|---|---|---|---|
| `ru` | учитель | объяснения с терминологией: падежи, окончания, -тся/-ться, ударение, жи-ши, подлежащее/сказуемое | 32 | 134 с |
| `kk` | ученик | ответы и вопросы по-казахски: «Түсінбедім», «Қайталап айтып берсеңіз болады ма?», «Бұл сөз қай септікте?» | 30 | 60 с |
| `mixed` | учитель и ученик | реплики с переключением кода внутри фразы: «Апай, предложный падеж деген не?», «Молодец! Енді окончание дегенді тап.» | 30 | 103 с |
| `ru/degraded`, `mixed/degraded` | — | те же реплики, пропущенные через ffmpeg: 16 кГц, полоса 250–3400 Гц, розовый шум (~20–25 дБ SNR) — имитация плохого канала Zoom | 62 | 237 с |

Тексты написаны вручную под сценарий пилота (см. `backend/benchmarks/utterances.py`), числа записаны словами, чтобы WER не наказывал за формат «42» против «сорок два».

TTS: **Piper** (`piper-tts` 1.8.0), голоса `ru_RU-irina-medium`, `ru_RU-dmitri-medium` (учитель) и многоголосый `kk_KZ-issai-high` (ученик; это голоса ISSAI, Назарбаев Университет). В смешанных репликах русские фрагменты ученика озвучены казахским голосом — казахский акцент на русских словах как раз то, что пилот услышит в реальности; казахские фрагменты учителя — тоже казахским голосом (учитель в казахской школе, как правило, казахоязычный). Голоса скачаны с зеркала GitHub-релизов sherpa-onnx, потому что Hugging Face недоступен; это те же файлы `.onnx`, что в `rhasspy/piper-voices`.

Все файлы — 16 кГц mono PCM, как на входе STT в продуктовом пайплайне (`CONTRACT.md` §1).

### 1.2 Модели и рантайм (`backend/benchmarks/stt_bench.py`)

* Модели OpenAI Whisper: **tiny, base, small, medium, large-v3-turbo** — веса int8, CPU, 4 потока, жадное декодирование.
* Рантайм: продуктовый провайдер `whisper_local` использует **faster-whisper** (CTranslate2), но его модели живут только на Hugging Face. В этой среде использованы те же веса Whisper, экспортированные в ONNX (int8) проектом k2-fsa/sherpa-onnx и выложенные на GitHub, в двух вариантах запуска:
  * **`whisper-onnx`** — наш собственный декодер поверх `onnxruntime` (`benchmarks/whisper_onnx.py`): log-mel как в OpenAI Whisper, жадный поиск, определение языка, **побайтовая сборка текста из BPE-токенов**. Это основной backend в таблицах ниже.
  * **`sherpa-onnx`** — готовый рантайм. У его Python API есть дефект: байтовые BPE-токены возвращаются пустыми строками, поэтому казахские буквы **ұ ө ә ң ғ ү һ** (часто и **қ**) просто выпадают из текста («Бұл сөз қай» → «Бл сз к»). Для русского это почти незаметно, для казахского завышает WER/CER. Его цифры мы приводим для сравнения и как предупреждение тем, кто захочет использовать sherpa-onnx для kk.
  * Бенчмарк поддерживает все три (`--backend auto|faster-whisper|whisper-onnx|sherpa-onnx`); при доступном Hugging Face `auto` выберет faster-whisper. Ожидаемые WER между faster-whisper и `whisper-onnx` совпадают с точностью до деталей декодирования (у faster-whisper по умолчанию beam 5 и fallback по температуре — он будет чуть лучше и устойчивее к зацикливанию); скорость faster-whisper на CPU выше (CTranslate2 оптимизирован под int8 на x86).
* Метрики: **WER** и **CER** через `jiwer` после нормализации (нижний регистр, ё→е, вся пунктуация и дефисы → пробел, схлопывание пробелов); **RTF** = время декодирования / длительность аудио (без времени загрузки модели).
* Режимы языка: принудительный `ru`, принудительный `kk`, автоопределение. На `mixed` дополнительно считаем **распределение определённого языка**.
* Защита от перегрева CPU: модели гоняются последовательно; после трёх реплик бенчмарк экстраполирует время прогона и пропускает прогон, если он превышает `--max-run-minutes` (по умолчанию 25). Пропуски фиксируются в результатах.

Полные таблицы: `backend/benchmarks/results/RESULTS.md` и `results/*.json` (с гипотезами по каждой реплике).

### 2.1 Что это значит для пилота

* **Русский (речь учителя).** Уже `small` даёт приемлемый для аналитики транскрипт на чистой синтетике; `medium` и `large-v3-turbo` заметно точнее на грамматических терминах («предложный», «-ться»). На «деградированном» аудио падение умеренное — Whisper устойчив к полосовому ограничению и ровному шуму; реальные помехи (эхо, перебивания, микрофон ноутбука) ударят сильнее.
* **Казахский (речь ученика).** Zero-shot Whisper слаб: маленькие модели практически не распознают, на `medium`/`turbo` остаются грубые ошибки. Это согласуется с внешними данными: Whisper large-v3 на FLEURS kk — WER порядка 30–40 %, дообученные казахские варианты — 12–18 % (см. §3.9). Для фраз ученика на казахском **нужен провайдер с реальной поддержкой kk или дообученная модель**, иначе LLM получит «шум» в самых важных местах — вопросах ученика («Түсінбедім», «қайталап»).
* **Смешанная речь.** Автоопределение языка Whisper работает **на всю реплику** (по первым 30 с) и почти всегда выбирает `ru`: казахские вставки либо транслитерируются русскими буквами, либо «переводятся». Принудительный `ru` даёт такой же результат, принудительный `kk` ломает русскую часть. Вывод: ни один вариант Whisper не решает ru↔kk внутри одной фразы; реалистичная стратегия — **принудительный `ru` + отдельный проход/провайдер для казахских сегментов** или облачный провайдер с настоящим code-switching (см. §3).
* **Скорость.** На 4 vCPU `small` работает в несколько раз быстрее реального времени, `medium` — около реального времени, `large-v3-turbo` — медленнее `medium` на CPU из-за большого энкодера. Для пилота (десятки уроков в день) `small`/`medium` на CPU достаточно; для сотен уроков — GPU или облако.

### 2.2 Ограничения бенчмарка (честно)

1. **Синтетика.** TTS не воспроизводит детскую речь, запинки, перебивания, смех, фон класса, компрессию Zoom. Ожидайте WER на реальных записях в 1,5–3 раза выше.
2. **Один голос на язык.** Многоголосый `kk_KZ-issai-high` даёт 6 дикторов, русских голосов два. Разброса по возрасту нет.
3. **Короткие реплики (2–8 с).** Контекст длинных монологов, где Whisper склонен к «галлюцинациям» и повторам, не проверялся.
4. **Переключение кода склеено из фрагментов разных голосов** — смена тембра на границе языков может даже *помогать* модели по сравнению с реальной речью одного человека.
5. **Нормализация прощает орфографию, но не морфологию.** Для русского WER на уровне слов строг: «окончание» ≠ «окончании».
6. **Рантайм.** ONNX-экспорт вместо faster-whisper: веса одни, но декодер жадный без fallback по температуре (зацикливания на kk мы обрезаем эвристикой), RTF на CPU не переносим напрямую.
7. **Диаризация не оценивалась** — в датасете одна реплика = один говорящий.
8. **wav2vec2 / казахские дообучения Whisper не измерены** — модели на Hugging Face недоступны из среды.

### 3.2 OpenAI

`whisper-1` и `gpt-4o-transcribe` принимают один язык на запрос (параметр `language`, в новых моделях `languages`), оба знают казахский (он в списке 57 языков с WER < 50 % в документации). Диаризация — отдельная модель `gpt-4o-transcribe-diarize` (вывод `diarized_json`, prompt не поддерживается, только `/v1/audio/transcriptions`). Цена whisper-1 и gpt-4o-transcribe — $0.006/мин ≈ $0.36/ч; mini — $0.18/ч; у diarize токенная тарификация ($2.50/M аудио-токенов, ≈ $0.36/ч по агрегаторам — проверить). Файл ≤ 25 МБ, урок на 60 минут придётся режть на части или сжимать в Opus/MP3. Резидентность данных — только для одобренных enterprise-проектов (EU, UK, JP, IN и др.); казахстанского региона нет. **Не измерялось здесь.**

### 3.3 Deepgram

Nova-3 поддерживает русский (моно-модель обновлена в августе 2026) и **казахский (добавлен 3 сентября 2026, `language=kk`, batch и streaming)**. Это самая дешёвая из больших облачных моделей ($0.0043/мин ≈ $0.26/ч batch). Но режим мультиязычного code-switching (`language=multi`) покрывает 10 языков **без казахского** — смешанную ru↔kk речь Nova-3 корректно не разберёт; при `language=kk` русские фрагменты будут искажены и наоборот. Диаризация — add-on (~$0.12/ч). EU-эндпоинт `api.eu.deepgram.com` (GA декабрь 2025), self-hosted — enterprise. Модель для kk новая, качество на детской речи неизвестно — **первый кандидат на A/B с реальными записями**.

### 3.4 AssemblyAI

Universal-2 — 99 языков, русский в группе «high accuracy», казахский поддерживается (отдельная языковая страница, $0.15/ч). Новая Universal-3.5 Pro (18 языков, встроенный code-switching) **не включает ни ru, ни kk**, так что для нас актуальна только Universal-2 с одним языком на файл (или автодетектом одного языка). Диаризация +$0.02/ч. Регионы US и EU по одной цене. Дешёвый и зрелый вариант для **русской** части, для казахской — проверять.

### 3.5 Google Cloud Speech-to-Text v2

Chirp 2/Chirp 3 отлично работают с русским, умеют диаризацию и мультиязычный ввод, но **казахский в Chirp 3 не найден**; `kk-KZ` числится только у старых моделей (`chirp` в `asia-southeast1`, `long` фактически без функций — на форуме Google пользователи сообщают, что не работает). Стандартная цена высокая ($0.96/ч), dynamic batch дёшев ($0.18/ч), но с задержкой до 24 часов — для отчёта «после урока» это приемлемо, если центр готов ждать до следующего утра. Для пилота — не лучший выбор из-за kk.

### 3.6 ElevenLabs Scribe

Scribe v1/v2: 99 языков, включая казахский, диаризация до 32 спикеров, $0.22/ч. Вендор заявляет очень низкий WER на FLEURS kk (3,1 %), независимых подтверждений нет; конкурент (Soniox) утверждает, что на разговорном акцентном казахском ошибок больше. Автоопределение языка на файл есть; устойчивое переключение ru↔kk внутри реплики — вопрос, который надо проверить на реальных записях. **Второй кандидат на A/B.**

### 3.7 Yandex SpeechKit

Единственный провайдер с **казахстанским регионом (`kz1`, ЦОД в Караганде, оператор ТОО «Облачные Сервисы Казахстан», биллинг в тенге)** и одновременно сильным русским и казахским: язык определяется по предложениям в режиме автоопределения, т. е. смена языка между фразами (учитель по-русски — ученик по-казахски) поддерживается нативно; внутри одного предложения — нет. Есть определение дикторов в асинхронном режиме. Цены для региона Казахстан — на отдельной странице (в выдаче они не отдались, по старым публичным тарифам RU порядок десятков рублей за час, т. е. ≈ $0.4–0.6/ч — **проверить**).

Резидентность: формально данные остаются в Казахстане, что упрощает соблюдение ст. 12 Закона РК «О персональных данных и их защите» (локализация баз персональных данных). Но материнская компания — российская, что для школ и родителей может быть чувствительно (санкционные ограничения на оплату и ПО, вопросы доверия, политические риски при работе с записями детей). Рекомендуем оценивать не только технически; подробнее — `docs/LEGAL_KZ.md`.

### 3.8 Azure AI Speech и AWS Transcribe

Azure: `kk-KZ` и `ru-RU` поддерживаются, диаризация включена в batch, непрерывное определение языка (continuous LID) принимает до 10 языков-кандидатов и переключает их по сегментам — технически это **единственный крупный облачный механизм, который может переключаться между ru и kk внутри одной записи**, но качество kk и реакция на короткие вставки не измерены. Batch ≈ $0.18/ч (realtime ~$1–1.6/ч). Ближайшие регионы — UAE North, Central India, EU.

AWS Transcribe: `ru-RU` batch и streaming, `kk-KZ` только batch, диаризация включена, но $1.44/ч — дороже всех, без явных преимуществ для нашего кейса.

### 3.9 Локальные казахские модели

* **ISSAI KSC2** (Назарбаев Университет) — открытый корпус ~1,2 тыс. часов казахской речи, основа большинства дообучений; есть структурированная версия `InflexionLab/ISSAI-KSC2-Structured`.
* **`InflexionLab/sybyrla`** — Whisper large-v3, дообучен на казахском **и русском**, WER ≈ 17,7 % на тесте KSC2. Самый интересный кандидат для ru↔kk.
* **`shyngys879/kazakh-whisper-large-v3-turbo`** — ~1500 ч публичных данных, WER 11,8 % на FLEURS kk (zero-shot turbo — 19,75 %, large-v3 — 31,1 %); turbo-архитектура быстрее на CPU.
* **`KRASR/kazakh-russian-asr-whisper-large-v3-lora`**, **`nur-dev/Qwen3-ASR-0.6B-kk-ru-en`**, **`olzhasAl/whisper-large-v3-tulpar`**, **`BuzzASR/kazakh`** — другие ru/kk варианты, качество по карточкам.
* **wav2vec2-XLSR Kazakh** (напр. `DrishtiSharma/wav2vec2-large-xls-r-300m-kk-with-LM`, модели на KSC v1.1): WER ≈ 20–22 % на FLEURS/KSC, CTC без языковой модели — хуже Whisper-дообучений, но очень быстро на CPU.

Все они совместимы с faster-whisper после конвертации в CTranslate2 (`ct2-transformers-converter`), т. е. могут стать вторым локальным провайдером `whisper_local` с другим `WHISPER_MODEL`. **Не измерялось здесь** (Hugging Face недоступен); ссылки и цифры — из карточек моделей: [sybyrla](https://huggingface.co/InflexionLab/sybyrla), [kazakh-whisper-large-v3-turbo](https://huggingface.co/shyngys879/kazakh-whisper-large-v3-turbo), [KSC2](https://huggingface.co/datasets/issai/Kazakh_Speech_Corpus_2), [BuzzASR/kazakh](https://huggingface.co/BuzzASR/kazakh), [статья о Whisper для казахского](https://arxiv.org/pdf/2408.05554).

## 4. Рекомендация для MVP

### 4.1 Провайдер по умолчанию для пилота

**`whisper_local` (faster-whisper, `WHISPER_MODEL=small` для демо / `medium` для пилота, int8, CPU) + принудительный язык `ru`** — уже заложено в `.env.example` и `providers/stt/whisper_local.py`.

Почему:

1. Записи уроков с детьми не покидают сервер центра/нашей инфраструктуры в Казахстане — снимается вопрос трансграничной передачи и согласий на передачу третьим лицам на старте пилота.
2. Ноль переменных затрат, никакой зависимости от ключей и квот.
3. Русская речь учителя (основной объём аудио и основа аналитики) распознаётся достаточно для LLM-анализа: модель находит ошибки по смыслу, а не по точной орфографии.
4. Казахские реплики ученика будут распознаны плохо — **это известное ограничение пилота**, его надо честно записать в `LessonAnalysis.limitations` и `language_notes` (промпт уже предусматривает оговорки о качестве транскрипта). Короткие казахские фразы-сигналы («түсінбедім», «қайталап») LLM часто восстанавливает по контексту даже из искажённого транскрипта, но полагаться на это нельзя.

Как только появятся первые согласованные реальные записи — переходить к A/B из §4.2.

### 4.2 Что проверять следующим (A/B на реальных записях с согласием)

Порядок по ожидаемой отдаче:

1. **Deepgram Nova-3** (`language=kk` для реплик ученика / `ru` для учителя, либо два прохода) — новый kk, самая низкая цена, EU-эндпоинт. Главный вопрос — детская казахская речь и смешанные реплики.
2. **ElevenLabs Scribe v2** — заявленный сильный kk, автоопределение языка, диаризация в комплекте, $0.22/ч.
3. **Локальное дообучение Whisper на kk+ru** (`sybyrla` / `kazakh-whisper-large-v3-turbo`, конвертация в CT2) — закрывает kk без выноса данных; проверить, не деградирует ли русский.
4. **Yandex SpeechKit в `kz1`** — технически лучший матч (ru+kk по предложениям, регион в РК), но решение о нём — за центром и юристом из-за происхождения компании.
5. Azure continuous LID (ru-RU + kk-KZ) — как эксперимент с code-switching, если 1–3 не справятся.

Методика A/B: 5–10 реальных уроков, ручная расшифровка 10-минутных фрагментов (учитель + ученик), тот же `stt_bench.py` с манифестом реальных записей (формат JSONL совпадает), метрики WER по языкам + доля правильно распознанных казахских реплик ученика + качество итогового `LessonAnalysis` по оценке методиста.

### 4.3 Стоимость за час урока (STT)

| Вариант | $/час аудио | Комментарий |
|---|---|---|
| faster-whisper `medium` на 4 vCPU | ≈ 0.03–0.10 | только аренда VM, RTF ≈ 1 на CPU; с GPU — копейки |
| AssemblyAI Universal-2 + диаризация | 0.17 | ru хорош, kk — проверять |
| ElevenLabs Scribe v2 | 0.22 | диаризация включена |
| Deepgram Nova-3 batch + диаризация | ≈ 0.38 | ru + kk монолингвально |
| OpenAI gpt-4o-transcribe(-diarize) | ≈ 0.36 | без kk-специфики |
| Google STT v2 dynamic batch / standard | 0.18 / 0.96 | kk практически нет |
| Azure batch / realtime | ≈ 0.18 / 1.0–1.6 | ru+kk, LID |
| Yandex SpeechKit (kz1) | ≈ 0.4–0.6 (проверить) | ru+kk, данные в РК |
| AWS Transcribe | 1.44 | дорого |

При 20 уроках в день по 60 минут месячный бюджет STT в облаке — от ~$90 (AssemblyAI) до ~$230 (Deepgram с диаризацией); локально — стоимость одной VM.

### 4.4 Диаризация: провайдер или pyannote

Пилот — один учитель и один ученик, поэтому задача простая (2 спикера), но критичная: доли речи (`teacher_talk_share`), «ответил сам / повторил за учителем», подсчёт самостоятельных решений — всё опирается на то, кто говорит.

Рекомендация:

* **Фаза 1 (локальный Whisper):** `pyannote/speaker-diarization-3.1` локально (CPU ≈ реальное время на 4 vCPU, лицензия MIT на код, веса требуют принятия условий на Hugging Face; альтернатива без HF — диаризация в sherpa-onnx с моделями на GitHub). Назначение ролей: спикер, у которого больше слов/времени и больше вопросительных конструкций, — учитель; подтверждение по первым 2 минутам (учитель начинает урок). Записывать в `transcripts.speaker_map`. Запасной эвристический режим при сбое диаризации: **все сегменты `unknown`**, LLM получает инструкцию определять говорящего по содержанию — хуже, но не блокирует пайплайн.
* **Фаза 2 (облачный провайдер):** использовать диаризацию провайдера (Deepgram/ElevenLabs/AssemblyAI — все дают метки спикеров с таймкодами), pyannote оставить как fallback. Это проще и дешевле поддерживать, а в сценарии 1:1 качество провайдерской диаризации достаточно.
* **Zoom-специфика:** если центр включает в Zoom запись «отдельные аудиодорожки для каждого участника», диаризация не нужна вовсе — два файла = два спикера. Это стоит рекомендовать центрам как настройку по умолчанию.

### 4.5 LLM: Anthropic по умолчанию, OpenAI как альтернатива

Задача — мультимодальный анализ: транскрипт ~6 тыс. токенов + до 20 кадров + промпт со схемой `LessonAnalysis` (~4 тыс. токенов) → строго типизированный JSON (~4–6 тыс. токенов на выходе).

**По умолчанию — Anthropic Claude Sonnet 5.5** (`LLM_MODEL=claude-sonnet-5-5`, как в `.env.example`): structured outputs по JSON-схеме, уверенная работа с русским текстом и Cyrillic-OCR на кадрах (доска, тетрадь ученика), 1M контекст — хватит и на двухчасовые уроки без усечения транскрипта. Для сложных уроков или методического разбора — `claude-opus-5-5`; для черновых/массовых прогонов — `claude-haiku-5-5`.

Оценка стоимости одного урока (входных ≈ 6k транскрипт + 4k промпт/схема + 20 кадров; кадр 1280×720 ≈ 1 230 токенов по формуле `w·h/750`, при даунскейле до 1024×576 ≈ 790 токенов — рекомендуем даунскейл, это ~16 тыс. токенов на 20 кадров):

| Модель | $/M вход / выход | Вход ≈ 26–35k ток. | Выход ≈ 5k ток. | **Итого за урок** |
|---|---|---|---|---|
| Claude Sonnet 5.5 | 2 / 10 | $0.05–0.07 | $0.05 | **≈ $0.10–0.12** (batch API −50 % → ≈ $0.06) |
| Claude Opus 5.5 | 4 / 20 | $0.10–0.14 | $0.10 | ≈ $0.20–0.24 |
| Claude Haiku 5.5 | 0.10 / 0.50 | < $0.01 | < $0.01 | ≈ $0.006 |
| OpenAI GPT-5 (альтернатива, `LLM_PROVIDER=openai`) | ≈ 1.25 / 10 (проверить) | ≈ $0.04 | $0.05 | ≈ $0.09; GPT-5-mini ≈ $0.02 |

Цены Anthropic — первичные тарифы API (октябрь 2026); цены OpenAI по агрегаторам, токенизация изображений у OpenAI другая (тайлы 512 px) — **проверить** перед бюджетированием. Итого на урок: **STT + LLM ≈ $0.10–0.50** в облачном варианте и ≈ $0.10–0.15 при локальном STT; LLM — доминирующая, но всё равно скромная статья.

Практика для контроля бюджета: кэшировать системный промпт со схемой (prompt caching — он одинаков для всех уроков), не отправлять кадры-дубликаты (dHash-дедуп уже в `pipeline/media.py`), ограничивать `LLM_MAX_FRAMES=20`, использовать Batch API для ночной обработки.

Резидентность LLM: Anthropic API — инференс в США (`inference_geo="us"`) или глобально; EU-инференс доступен через AWS Bedrock (EU-профили) и Vertex AI. На LLM уходит **текст транскрипта и кадры**, не аудио и не видео целиком, но персональные данные ребёнка там есть — требуется согласие родителя на передачу обработчику за рубеж и минимизация (не передавать ФИО в промпт; в пайплайне используются только id). См. `docs/LEGAL_KZ.md`.
